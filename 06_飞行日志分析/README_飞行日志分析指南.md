# PX4 飞行日志分析指南

> 适用项目：Pixhawk 6C + X400 + MTF-02  
> 日志格式：`.ulg`（PX4 原生日志）  
> 用途：飞行后诊断、排查异常、评估飞行质量  

---

## 一、什么是 .ulg 文件

`.ulg` 是 PX4 飞控在飞行过程中自动记录的二进制日志文件。它保存了：

- 所有传感器的原始数据（IMU、气压计、磁罗盘、光流、测距）
- EKF2 估计器的内部状态
- 电机输出、遥控输入
- GPS 数据（如果有）
- 故障安全触发记录
- 飞行模式切换记录

**日志存放在飞控的 SD 卡中**，飞行结束后取出 SD 卡即可获取。

---

## 二、推荐的日志文件命名规则

为避免团队内部日志混乱，建议按以下格式命名：

```
log_序号_日期_时间.ulg
```

| 示例 | 说明 |
|---|---|
| `log_27_2026-5-26-07-34-02.ulg` | 第 27 次飞行，2026 年 5 月 26 日 07:34 起飞 |

> 飞控自动生成的日志文件通常按编号递增（`log_1.ulg`、`log_2.ulg`……），取出后可根据飞行记录补充日期和时间。

## 四、方法一：PX4 官方在线分析（推荐首选）

### 4.1 操作步骤

1. 打开浏览器，访问 **https://review.px4.io/**
2. 点击页面中间的 `Browse` 按钮，或在页面任意位置拖入 `.ulg` 文件
3. 等待上传——大文件可能需要 1-2 分钟
4. 上传完成后，页面自动跳转到分析报告

### 4.2 报告怎么看

页面顶部是**摘要信息**：

| 指标 | 含义 |
|---|---|
| Flight Duration | 飞行时长 |
| Max Altitude | 最大高度 |
| Max Velocity | 最大速度 |
| Flight Mode Changes | 飞行模式切换次数 |
| Events / Faults | 事件和故障记录 |

往下翻，逐个看以下板块：

#### (1) Vehicle Attitude（姿态）

- 红色 = Roll（滚转），绿色 = Pitch（俯仰），蓝色 = Yaw（偏航）
- **正常**：三根线基本平稳，偏航在 0~360° 间平滑变化
- **异常**：剧烈抖动、突然跳变

#### (2) Vibration（振动）⚠️ 很重要

- **正常**：IMU 三轴振动都在绿色范围内（< 30 m/s²）
- **超标**：出现红色区域，说明：
  - 桨不平衡
  - 螺丝松动
  - 电机轴承有问题

#### (3) Estimator（估计器）

- 显示 EKF2 对各传感器数据的"信任程度"
- **正常**：所有 Innovation 值在绿色带内
- **异常**：出现红色尖峰，说明传感器数据与 EKF 预测不一致，常见原因：
  - 光流数据质量差（地面纹理不够、光照不足）
  - 测距数据有跳变（地面有障碍物、超出量程）
  - 机身振动太大

#### (4) Actuator Controls（电机输出）

- 四条线分别代表 4 个电机的输出值（归一化 0~1）
- **正常**：四条线基本接近，曲线趋势一致
- **异常**：某条线明显高于其他三条 → 该电机负载过大或动力不足

#### (5) Battery（电池）

- 电压曲线随时间下降
- **正常**：平滑下降，没有突然掉压
- **异常**：飞行过程中电压骤降 → 电池老化或温度过高

#### (6) GPS / Optical Flow（定位）

- 显示定位源的可用状态
- 光流质量 `quality` 值 > 50 算好，< 20 说明纹理不够

### 4.3 如何分享给他人分析

点击页面右上角的 **"Share"** 按钮，复制生成的链接。把这个链接发给团队成员或 AI，其他人就能在线看到完整的分析报告。

## 五、方法二：PlotJuggler 桌面工具

### 5.1 安装

1. 访问 https://plotjuggler.io/
2. 下载 Windows 安装包
3. 双击安装（一路点击"下一步"）

### 5.2 使用

1. 打开 PlotJuggler
2. 点击 `Load Data` → 选择 `.ulg` 文件
3. 左侧出现所有数据字段列表，双击字段名即可在右侧画出曲线
4. 按住鼠标左键拖动可缩放，滚轮可平移

### 5.3 常用字段速查

| 你想看什么 | 双击哪些字段 |
|---|---|
| 飞机姿态 | `vehicle_attitude.roll / pitch / yaw` |
| 飞行速度 | `vehicle_local_position.vx / vy / vz` |
| 位置变化 | `vehicle_local_position.x / y / z` |
| 振动情况 | `sensor_accel.x / y / z` |
| 电机输出 | `actuator_outputs.output[0] ~ output[3]` |
| 光流质量 | `vehicle_optical_flow.quality` |
| 光流像素流 | `vehicle_optical_flow.pixel_flow[0] / pixel_flow[1]` |
| 测距读数 | `distance_sensor.current_distance` |
| 遥控输入 | `manual_control_setpoint.roll / pitch / yaw / throttle` |
| 电池电压 | `battery_status.voltage_v` |
| EKF 状态 | `estimator_status_flags.cs_opt_flow / cs_rng_hgt` |
| GPS 卫星数 | `satellite_info.count` |

## 六、方法三：AI 辅助深度分析

### 6.1 什么时候用

- 方法一看完报告但看不懂问题在哪
- 飞行出现了异常但 PX4 在线报告没有明确结论
- 想深入分析某个具体问题（光流漂移、高度不稳等）

### 6.2 操作步骤

1. 打开 https://review.px4.io/ 上传日志
2. 点 **"Share"** 获取分享链接
3. 把分享链接发给 AI 助手（例如本项目使用的 AI），AI 会帮你：
   - 下载并解析日志数据
   - 对照项目参数配置找出异常
   - 给出中文诊断报告和改进建议

### 6.3 你也应该一起提供的信息

为了让 AI 更好地分析，分享日志时最好附带：

| 信息 | 示例 |
|---|---|
| 飞行模式 | "Position 模式，前 30 秒正常，突然开始漂移" |
| 飞行高度 | "大约 0.8 m 高度" |
| 问题现象 | "飞机缓慢往左前方漂移，遥控器不修正就会撞网" |
| 飞行环境 | "室内木地板，日光灯照明，地面纹理清晰" |
| 参数版本 | "使用参数 2.2.params" |

## 七、常见问题速查表

这是在 X400 + MTF-02 + 室内无 GPS 场景下，根据日志可以快速定位的常见问题：

| 现象 | 在日志中看什么 | 可能的参数修复 |
|---|---|---|
| 飞机高度上下跳动 | `distance_sensor.current_distance` 频繁跳变 | 检查地面是否有障碍物干扰测距 |
| 飞机水平漂移 | `vehicle_local_position.x / y` 持续偏移 | 检查 `EKF2_OF_QMIN`，光流 `quality` 是否偏低 |
| 飞机抖动/震荡 | `sensor_accel.x/y/z` 振动超标 | 平衡桨叶，拧紧螺丝，降低 MPC PID 增益 |
| 电机发烫/推力不足 | `actuator_outputs` 某路明显偏高 | 检查该电机/电调/螺旋桨 |
| 解锁后自动上锁 | `failsafe_flags` 有触发 | 查看 QGC 错误提示，检查 `COM_ARM` 相关参数 |
| 光流数据中断 | `vehicle_optical_flow.quality` 断崖式下跌 | 检查 MTF-02 供电和接线 |
| Position 模式无法切换 | `estimator_status_flags.cs_opt_flow = False` | 检查 `EKF2_OF_CTRL`、`EKF2_HGT_REF` |

## 九、团队协作建议

1. **每次飞行后**：把 SD 卡日志导出到电脑，按"序号_日期_时间"格式重命名后放入此文件夹
2. **发现异常时**：先在 PX4 在线工具看报告，如果无法确定原因，把分享链接发到团队群，附上"问题现象描述"
3. **重大问题排查后**：在此文件夹中新建一个 Markdown 分析报告（参考已有的分析报告格式），记录问题和解决方案
4. **定期回顾**：每完成一个阶段的测试，回顾此阶段的日志分析报告，确保问题已闭环
