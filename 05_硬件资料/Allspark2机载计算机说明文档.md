## 1. 产品概述

### 1.1 产品定位

Allspark-Orin NX 是 AMOVLAB 专为小型机器人及边缘 AI 应用打造的高性能、小体积 AI 边缘计算机。它内置 **NVIDIA Jetson Orin NX** 核心模组，在 25W 功耗下提供 **100 TOPS** 的 AI 推理算力，适合部署于无人机、无人车、机械臂等空间受限且对实时性要求高的移动平台。

### 1.2 核心特点

| 特点 | 说明 |
|:---|:---|
| **高算力** | 100 TOPS INT8 算力，支持主流深度学习框架 |
| **小体积** | 102.5 × 62.5 × 31 mm，约 188g |
| **强接口** | 双网口、双 MIPI CSI、CAN、多 UART/SPI/I2C/GPIO |
| **内置存储** | 128GB SSD（M.2 NVMe，可扩展） |
| **主动散热** | 内置散热鳍片 + 静音风扇 |
| **宽温工作** | -20℃ ~ 50℃ |
| **机器人专用** | 铝合金外壳，抗振设计，支持 3S~6S 锂电池直供 |

### 1.3 版本说明

本说明书针对 **25W 普通版**（型号 IA16O_V1）。另有 Super 版本（45W，157 TOPS），外形尺寸和重量不同，请注意区分。

## 4. 电气特性与供电要求

### 4.1 电源接口

- **接口类型**：XT30
- **输入电压**：DC 10 V ~ 26 V
- **建议输入**：DC 12 V @ 2.5 A
- **极性**：接入前务必确认极性正确，反接可能烧毁设备

> ⚠️ **警告**：
> 1. 与电机类设备共用电源时，必须使用锂电池供电，或分开隔离供电，避免反电动势损坏机载计算机。
> 2. 接入集成系统前，请用示波器确认电源启动时无超过 26V 的过压脉冲。

### 4.2 功耗输出能力

Allspark-Orin 可为外部设备供电，但需注意总功耗限制：

| 输出通道 | 电压/电流 | 最大功率 |
|:---|:---|:---|
| 3.3V 输出 | 3.3V @ 3A | 9.9 W |
| 5.0V 输出 | 5.0V @ 5A | 25 W |

> 注意：外部设备总功耗 + 机载计算机自身功耗（最大 27W）不得超过电源适配器总输出功率。

### 4.3 推荐供电方案

| 应用场景 | 推荐方案 |
|:---|:---|
| 无人机/无人车 | 3S~6S 锂电池直供（11.1V~22.2V） |
| 实验室桌面调试 | DC 12V/5A 稳压电源适配器 |
| 高负载外设（多相机+USB设备） | 确保电源能提供 ≥8A 峰值电流 |

## 5. 首次使用快速入门

### 5.1 开箱检查清单

- [✅] Allspark-Orin NX 主机 ×1
- [✅] WiFi 天线（如购买带 WiFi 版本）
- [✅] M2.5 × 5mm 固定螺钉
- [✅] 电源线（XT30 接口）
- [✅] 确认版本：25W 版（厚度 31mm，重量约 188g）

### 5.2 首次上电步骤

1. **连接显示器**：使用 Micro HDMI 转 HDMI 线连接显示器（最大支持 1920×1080）
2. **连接输入设备**：将 USB 鼠标/键盘接入 Type-A 或 Type-C 接口
3. **连接电源**：使用 XT30 电源线接入 DC 10~26V 电源
4. **观察指示灯**：红色电源灯亮起，风扇开始转动
5. **等待启动**：首次启动约需 30~60 秒

### 5.3 登录系统

| 项目 | 默认值 |
|:---|:---|
| **用户名** | `amov` |
| **密码** | 见设备标签或管理员 |
| **系统** | Ubuntu 20.04（基于 JetPack 5.1.4） |

### 5.4 网络连接

**方式一：有线连接**
- 使用网线接入 ETH1 或 ETH2（100Mbps）
- 系统默认 DHCP 自动获取 IP

**方式二：WiFi 连接（如带 WiFi 模块）**
- 点击桌面右上角网络图标
- 选择 WiFi 热点并输入密码
- 2.4G WiFi 无遮挡环境下有效范围约 20 米

**方式三：远程桌面（NoMachine）**
- 确保机载计算机与电脑在同一局域网
- 电脑端安装 NoMachine 客户端
- 输入机载计算机 IP 地址连接远程桌面

## 7. 接口详细定义与使用

### 7.1 以太网接口（ETH1 / ETH2）

| 参数 | 规格 |
|:---|:---|
| **数量** | 2 × 100Mbps |
| **ETH1** | 独立网口 |
| **ETH2** | 交换机扩展网口 |
| **用途** | 局域网连接、NoMachine 远程桌面、ROS 多机通信 |

### 7.2 USB 接口

| 接口 | 类型 | 规格 | 用途 |
|:---|:---|:---|:---|
| **USB1** | Type-A | USB 3.2 | 外接鼠标、键盘、U盘、相机等 |
| **USB2** | Type-C | USB 3.2 | 外接设备、调试 |
| **OTG** | Micro USB | USB 2.0 | **系统刷机/恢复专用** |

> 注意：OTG 接口仅用于刷机和系统维护，平时不建议作为普通 USB 使用。

### 7.3 MIPI CSI 相机接口（CSI0 / CSI1）

| 参数 | 规格 |
|:---|:---|
| **数量** | 2 × MIPI CSI 2 Lane |
| **支持相机** | 目前官方驱动支持 veye327、imx219 等 |
| **分辨率** | 最高 1920 × 1080 |

**快速测试命令：**
```bash
# 查看相机设备
dmesg | grep veye

# 30 对应 CSI0，31 对应 CSI1

# 打开相机预览
nvgstcapture-1.0
```

> 注意：MIPI 接口插拔时请小心操作，避免损坏接口。如需使用其他型号相机，需自行移植驱动或联系售后。

### 7.4 UART 串口（4 路）

| 接口 | 名称 | 信号电平 | 设备节点 | 用途 |
|:---|:---|:---|:---|:---|
| **UART0** | 通用串口 | 3.3V CMOS | `/dev/ttyTHS0` | 连接飞控/外设（本项目用） |
| **UART1** | 通用串口 | 3.3V CMOS | `/dev/ttyTHS1` | 连接飞控/外设 |
| **UART2** | 通用串口 | 3.3V CMOS | `/dev/ttyTHS2` | 连接飞控/外设 |
| **DEBUG** | 调试串口 | 3.3V CMOS | `/dev/ttyUSB0`（需转接） | 系统调试、查看启动日志 |

**引脚定义：**

| 串口 | PIN 1 | PIN 2 | PIN 3 | PIN 4 | PIN 5 | PIN 6 |
|:---|:---|:---|:---|:---|:---|:---|
| **UART0** | 5V0 输出 | 5V0 输出 | **RX** | **TX** | GND | GND |
| **UART1** | 3V3 输出 | **RX** | **TX** | GND | — | — |
| **UART2** | 3V3 输出 | **RX** | **TX** | GND | — | — |
| **DEBUG** | 3V3 输出 | **RX** | **TX** | GND | — | — |

> 所有串口的 RX/TX 均为 3.3V CMOS 电平，严禁接入 5V TTL 或 RS-232 设备（否则烧毁接口）。**UART0 的 PIN1/PIN2 为 5V 供电输出（最大 2A）**，可给外设供电，其余串口的 3V3 供电最大 1A。

**供电能力：**

| 串口 | 供电电压 | 最大电流 |
|:---|:---|:---|
| UART0 | 5.0V | < 2A |
| UART1 / UART2 / DEBUG | 3.3V | < 1A |

**使用步骤：**

```bash
# ① 查看有哪些串口设备
ls /dev/ttyTHS* /dev/ttyUSB*

# ② 添加用户到 dialout 组（串口权限，只需做一次）
sudo usermod -a -G dialout $USER
# 注销重新登录，或执行 newgrp dialout 临时生效

# ③ 回环测试（短接 RX 和 TX 引脚后验证自发自收）
echo "hello" > /dev/ttyTHS0     # 终端A发送
cat /dev/ttyTHS0                  # 终端B接收（另开窗口）
# 或使用图形工具
sudo apt install -y cutecom
cutecom
```

### 7.5 CAN 总线接口

| 参数 | 规格 |
|:---|:---|
| **速率** | 最高 5 Mbps |
| **电平** | CANH / CANL |
| **用途** | 连接无人机飞控（如 PX4/ArduPilot）、电机驱动器等 |

**启用与测试命令：**
```bash
# 加载 CAN 驱动
sudo modprobe can
sudo modprobe can_raw
sudo modprobe mttcan

# 查看 CAN 接口
ifconfig -a

# 设置回环测试模式
sudo ip link set can0 type can bitrate 500000 loopback on
sudo ip link set up can0

# 自发自收测试
# 终端1：监听
candump -x any &

# 终端2：发送
cansend can0 5A1#11.2233.44556677.88

# 关闭接口
sudo ip link set can0 down
```

## 8. 性能边界与使用限制

### 8.1 算力与功耗边界

| 指标 | 25W 版本 | 说明 |
|:---|:---|:---|
| **AI 算力** | 100 TOPS (INT8) | 实际推理性能受模型复杂度、批处理大小影响 |
| **GPU 频率** | 918 MHz | 频率锁定，不可超频 |
| **CPU 频率** | 2 GHz | 8 核同时满载时可能降频 |
| **整机功耗** | 6~27 W | 典型负载 15~20W，满载 25~27W |
| **持续功耗** | 建议 ≤25W | 长期超功耗运行可能触发过热保护 |

### 8.2 散热限制

- **散热方式**：主动散热（风扇 + 散热鳍片）
- **安装要求**：顶部和侧面出风口必须保持畅通，不可遮挡
- **高温环境**：接近 50℃ 上限时，风扇噪音增大，性能可能降频
- **建议**：高温环境下增加外部风道或降低负载

### 8.3 存储 I/O 边界

| 指标 | 规格 | 说明 |
|:---|:---|:---|
| **内置 SSD** | 128 GB NVMe | 系统+用户数据共用，建议保留 ≥20GB 余量 |
| **SSD 速度** | 典型 NVMe 速度 | 满足多路 1080p 视频录制需求 |
| **扩展存储** | USB 3.2 / 网络存储 | 大容量数据建议外接 SSD 或 NAS |

### 8.4 网络带宽边界

| 接口 | 速率 | 说明 |
|:---|:---|:---|
| **ETH1/ETH2** | 100 Mbps | 非千兆网口，大流量场景（如多路 4K 视频传输）可能成为瓶颈 |
| **WiFi** | 2.4G | 无遮挡约 20 米，穿墙后衰减明显 |
| **4G（如安装）** | 下行 30~45 Mbps / 上行 5~6 Mbps | 适合 telemetry 回传，不适合大带宽视频 |

### 8.5 接口电气边界

| 接口 | 电平 | 最大电流 | 注意 |
|:---|:---|:---|:---|
| **GPIO** | 3.3V | 小电流 | 不可直接驱动继电器/电机，需外接驱动板 |
| **UART** | 3.3V | / | 严禁接入 5V 电平设备，可能烧毁 |
| **SPI/I2C** | 3.3V | / | 上拉电阻需匹配 3.3V |
| **3.3V 输出** | 3.3V | 3A | 总功率 9.9W |
| **5.0V 输出** | 5.0V | 5A | 总功率 25W |

### 8.6 视频处理边界

- **最大编码能力**：1 路 4K60 H.265 或 6 路 1080p60 H.265
- **最大解码能力**：1 路 8K30 H.265 或 9 路 1080p60 H.265
- **实际并发路数**：受显存和 CPU 调度限制，建议实测验证

## 10. 系统维护与刷机

### 10.1 进入恢复模式（Recovery）

恢复模式用于系统刷写、备份和还原。

**步骤：**
1. 关闭系统电源
2. 使用 Micro USB 线连接 Allspark 的 OTG 端口与 Ubuntu 主机 USB 端口
3. **按住 REC 键不放**，给系统供电，保持 3 秒以上
4. **释放 REC 键**
5. 在主机终端输入 `lsusb`，若显示 **NVIDIA Corp. APX** 设备，则成功进入恢复模式

### 10.2 使用 SDK Manager 刷机（推荐）

**主机要求：**
- Ubuntu 18.04/20.04 系统
- 硬盘空间 ≥ 60 GB
- 安装 NVIDIA SDK Manager

**刷机步骤：**
1. 主机安装 SDK Manager，选择 **JetPack 5.1.4**（Jetson Linux 35.6.0）
2. Allspark 进入恢复模式（见 10.1）
3. SDK Manager 识别设备后，选择刷写目标为 **NVMe**
4. 设置用户名和密码（可自定义）
5. 等待刷写完成（约 30~60 分钟）
6. 刷写完成后自动重启进入系统

> ⚠️ **重要**：使用 SDK Manager 刷写官方镜像后，部分接口（SD 卡、WiFi/蓝牙）可能无法正常工作，需要打 AMOVLAB 官方补丁。请联系售后获取补丁文件。

### 10.3 镜像备份

**备份 eMMC 系统到镜像文件：**
```bash
# 进入恢复模式后，在主机执行
sudo ./flash.sh -r -k APP -G backup.img jetson-orin-nx-devkit mmcblk0p1
```

### 10.4 系统还原

**使用官方镜像还原：**
```bash
# 1. 下载官方镜像文件（.img.gz）
# 2. 使用 balenaEtcher 或 dd 命令写入 SD 卡
# 3. 进入恢复模式
```

## 11. 常见问题与排查

### 11.1 开机黑屏/无显示

| 现象 | 可能原因 | 解决方法 |
|:---|:---|:---|
| 电源灯亮，风扇转，黑屏 | HDMI 线或显示器问题 | 更换 HDMI 线，确认显示器输入源 |
| 电源灯亮，风扇转，黑屏 | 系统崩溃无法进入桌面 | 通过 Debug UART 查看启动日志，确认是否进系统 |
| 电源灯亮，风扇转，黑屏 | 显示器供电共地问题 | 显示器使用机载计算机 USB 供电，避免共地干扰 |
| 电源灯不亮 | 电源未接好或极性反 | 检查 XT30 接口和电源极性 |

**Debug UART 排查步骤：**
1. 使用 USB 转 TTL 线连接 DEBUG 接口（3V3、RX、TX、GND）
2. 打开串口调试助手（如 CuteCom、minicom），波特率 115200
3. 重新上电，观察启动日志
4. 若日志停止在某一阶段，根据错误信息排查

### 11.2 无法进入恢复模式

| 排查项 | 方法 |
|:---|:---|
| 检查 USB 线 | 更换高质量 Micro USB 数据线 |
| 检查按键时机 | 必须先按 REC 再通电，保持 3 秒以上 |
| 检查主机识别 | 主机执行 `lsusb`，确认出现 NVIDIA 设备 |
| 检查主机系统 | 必须使用 Ubuntu 系统，Windows 可能无法识别 |

### 11.3 WiFi/蓝牙无法使用

- 原因：SDK Manager 刷写官方镜像后，WiFi/蓝牙 DTB 未适配
- 解决：联系 AMOVLAB 售后获取适配补丁，更新设备树文件

### 11.4 4G 模块无法联网

| 排查项 | 方法 |
|:---|:---|
| SIM 卡 | 确认使用 Micro SIM 卡，已开通数据流量 |
| 天线 | 确认已安装 4G 天线 |
| 驱动 | 执行 `sudo dpkg -i amovUbuntuBsp.deb` 安装驱动 |
| 网络接口 | 确认拨号后生成 `usb0` 接口 |

### 11.5 过热/降频

| 现象 | 解决 |
|:---|:---|
| 风扇噪音大 | 正常，高温环境下风扇高速运转 |
| 性能下降 | 检查散热口是否遮挡，改善通风 |
| 温度接近 50℃ | 降低负载或增加外部散热 |

## 12. 安全注意事项

### 12.1 电气安全

1. **防反接**：XT30 电源接口有极性，反接可能瞬间烧毁设备
2. **防过压**：输入电压严禁超过 26V，建议使用稳压电源或锂电池
3. **防短路**：GPIO/UART 等接口避免金属物体短路
4. **防静电**：插拔 MIPI 相机等敏感接口时，建议佩戴防静电手环

### 12.2 机械安全

1. **固定螺钉**：仅限使用附送的 M2.5 × 5mm 螺钉，过长螺钉可能损坏内部器件
2. **散热保护**：安装后确认顶部和侧面散热出风口未被遮挡
3. **抗振设计**：铝合金外壳具备一定抗振能力，但极端振动环境建议增加减震垫

### 12.3 使用安全

1. **高温警告**：外壳温度可能较高，长时间运行后避免直接触摸散热片区域
2. **锂电池安全**：使用 3S~6S 锂电池时，注意电池过放保护和防火安全
3. **数据备份**：重要数据定期备份，刷机前必须备份
