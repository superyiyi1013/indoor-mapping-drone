# MAVLink 自动飞行说明 —— 从链路打通到脚本起飞

> 适用范围：Pixhawk 6C + X400 + PX4 + LQ 2.4G 数传 + Windows
>
> 核心链路：`电脑(网线) → 地面端LQ(LAN口, 192.168.1.200) → 无线2.4G → 天空端LQ(192.168.1.201) → Pixhawk TELEM1 → PX4`
>
> 前置条件：阶段 1-7 全部通过。


## 硬件连接

### 拓扑

```
电脑(网口, 192.168.1.123) ──网线── 地面端(LAN口, AP, 192.168.1.200)
                                        │ 无线 2.4G
                                 天空端(STA, 192.168.1.201)
                                        │ UART
                                    Pixhawk TELEM1
```

### 天空端 ↔ TELEM1 接线

| TELEM1 | 天空端 |
|--------|-------|
| TX | RX |
| RX | TX |
| GND | GND |

### 指示灯

- `LINK` 常亮 = 组网成功；`LINK` 闪烁 = 异常

### 天空端配置（地面端出厂不动）

| 项目 | 值 |
|------|-----|
| 串口波特率 | 115200 |
| 连接类型 | UDP |
| 目的 IP | `192.168.1.123` |
| 目的端口 | 14540 |

改完后保存并重启模块。

## 安全规则

1. **先拆桨**：装桨飞行前，所有脚本必须在拆桨下跑通
2. **遥控器在手**：随时切回 `Stabilized` 接管
3. **阶段 C 限高**：0.3~0.5 m，禁止超 1 m
4. **禁止 GPS 依赖**：脚本不含 RTL/Return
5. **阶段 B/C 先拆桨验证**，通过后再装桨

## 阶段 C：脚本起飞悬停

**目标**：脚本通过 MAVROS Offboard 模式完成统一自动起飞、定高悬停、人工接管或自动降落。

Offboard 模式：**脚本当大脑（规划路径），飞控当手脚（执行飞行）**。脚本以 `10 Hz` 持续发送本地位置 setpoint，PX4 负责姿态、电机和位置闭环。当前阶段06/阶段07所有自动飞行任务，凡是涉及起飞，必须统一调用 `flight_core.Fly.takeoff()`，任务脚本只负责“起飞之后”的悬停、前进、航点、接管等待等任务逻辑。

### 统一起飞流程

当前起飞程序不是简单给一个 1m 高度目标，而是分成 4 个连续状态，解决相对高度零点漂移、地面效应、起飞初段不果断、setpoint 回缩等问题。

```text
GROUND_BASELINE
  起飞前静止采样 2.5s 本地位置 z
  取均值作为本次 home_z
  后续高度均按 home_z - current_z 计算

LIFTOFF_STEP
  预发送 0.70m 台阶 setpoint
  切 OFFBOARD 并解锁
  持续给 0.70m 台阶目标，让飞机先明确离地

LIFTOFF_SETTLE
  检测到本次相对高度 >= 0.20m 后，认为已离地
  继续保持 0.70m 台阶目标
  直到高度至少达到 0.45m，且离地后保持时间 >= 0.8s

CLIMB_TO_TARGET
  从 0.70m setpoint 继续单调爬升到任务目标高度
  默认爬升速度 0.30m/s
  setpoint 只允许保持或上升，禁止回缩到当前高度
```

### 为什么必须先采样地面基准

现场已经确认：飞机放在地面上时，PX4/MAVROS 的相对高度可能显示 `0.2m`、`0.3m`、甚至 `0.5m`。因此程序不能直接把 `rel_alt` 当作真实离地高度。

统一起飞程序在解锁前会先采样地面高度：

```text
ground_alt = 起飞前 2.5s 的高度均值
agl = current_alt - ground_alt
```

实际代码使用 NED 坐标，等价关系是：

```text
相对本次地面高度 = home_z - current_z
```

这样即使 QGC 或 MAVROS 在地面显示 `0.3m`，程序仍然把当前地面作为 `0.00m` 来处理，避免误判“已经离地”或“已经到达目标高度”。

### 为什么使用 0.70m 台阶起跳

X400 当前起飞时存在地面效应、推力建立延迟和载重惯性。如果从 `0.00m` 很慢地线性爬升到 `1.00m`，飞机可能在地面上憋推力，表现为电机转速起来但高度长时间不变。

所以当前策略是先给一个明确的 `0.70m` 台阶目标：

```text
地面阶段：setpoint = 0.70m
刚离地：setpoint = 0.70m
高度到 0.45m 前：setpoint 仍保持 0.70m
进入爬升：setpoint 从 0.70m 继续增加到任务高度
```

关键约束：**起飞 setpoint 不能回缩**。之前出现过“保持阶段 setpoint 为 `0.60m`，实际高度约 `0.41m`，进入爬升后 setpoint 回到 `0.41m`”的问题，这会让 PX4 误以为高度误差消失，导致飞机在 40cm 附近停顿甚至短暂下降。新方案明确禁止这种回缩。

### 当前统一起飞参数

| 参数 | 当前值 | 含义 |
|------|--------|------|
| `GROUND_BASELINE_DURATION_S` | `2.5s` | 起飞前地面高度基准采样时长 |
| `LIFTOFF_TARGET_ALT_M` | `0.70m` | 起跳台阶目标高度 |
| `LIFTOFF_DETECTED_ALT_M` | `0.20m` | 判定已离地的本次相对高度 |
| `LIFTOFF_SETTLE_ALT_M` | `0.45m` | 离地后继续保持台阶目标直到至少达到该高度 |
| `LIFTOFF_HOLD_AFTER_DETECTED_S` | `0.8s` | 检测离地后最小保持时间 |
| `CLIMB_RATE_MPS` | `0.30m/s` | 离地稳定后爬升到目标高度的速度 |
| `CLIMB_TIMEOUT_S` | `20s` | 起飞爬升超时保护 |

这些参数只在 `03_SourceCode/flight_core/safety_config.py` 中统一管理。阶段06/阶段07任务脚本不再覆盖 `LIFTOFF_TARGET_ALT_M`、`CLIMB_RATE_MPS`、`CLIMB_TIMEOUT_S` 等起飞参数。

### 阶段任务与统一起飞的关系

所有阶段任务的边界应保持清晰：

```text
flight_core.Fly.takeoff()
  只负责可靠起飞到目标高度

阶段06/阶段07各任务
  只负责起飞后的悬停、接管、前进、避障、航点等动作
```

也就是说：

- 阶段06-03 低空悬停：统一起飞完成后，再执行悬停和降落。
- 阶段06-04 短距离前进：统一起飞完成后，再执行前进任务。
- 阶段06-05 避障停止：统一起飞完成后，再执行前向距离观察和停止逻辑。
- 阶段06-06 1m 起飞接管：统一起飞到 `1.00m` 后，再等待人工接管或自动降落。
- 阶段07 光流/局部航点任务：统一起飞完成后，再执行局部坐标稳定性、航点或路线测试。

禁止在单个阶段脚本中重新传入或覆盖起飞台阶高度、爬升速度、起飞超时等参数。否则不同测试的起飞行为会不一致，排查问题时无法判断是任务逻辑问题还是起飞逻辑问题。

### 降落触地判定

由于地面相对高度可能不回到 `0.00m`，降落也不能只依赖 `rel_alt < 0.05m`。当前公共降落逻辑采用组合判定：

```text
固定近地阈值：rel_alt < 0.05m
或
下降目标已到地面附近 + 实际低空高度 <= 0.25m + 高度在 2s 内变化 <= 0.03m
```

这样可以覆盖“实际已经着地，但高度读数停在 0.15m 左右”的情况，避免螺旋桨持续转动。

### C.1 拆桨：Offboard 与 setpoint 验证

1. 拆桨。
2. 运行阶段脚本，确认程序能连接 MAVROS 并持续发布 setpoint。
3. QGC 显示可切入 `OFFBOARD`，脚本输出进入统一起飞流程。
4. 遥控器切回 `Stabilized`，确认接管立即生效。
5. 反复 3 次，不允许出现 Offboard 信号丢失或模式切换卡死。

### C.2 装桨：统一起飞悬停

1. 开阔平地，无人/障碍。
2. 飞机静止放平，等待脚本采样地面基准。
3. 运行阶段06或阶段07任务脚本。
4. 观察起飞过程：先果断离地，再从台阶目标平滑爬升到任务高度。
5. 到达目标高度后，才进入对应任务动作。
6. 异常立即切 `Stabilized` 或人工接管。

### 通过标准

| 项目 | 条件 |
|------|------|
| 地面基准 | 起飞前完成 2.5s 采样，日志显示后续高度为本次基准高度差 |
| 离地动作 | 给 0.70m 台阶目标后能明确离地，无长时间贴地憋推力 |
| 起跳稳定 | 检测到 0.20m 后继续保持台阶目标，达到 0.45m 以上再进入爬升 |
| setpoint 连续性 | 起飞阶段 setpoint 不回缩，不再出现 0.60m 回落到当前高度的情况 |
| 目标高度 | 按任务目标高度悬停，阶段06-06 默认到 1.00m |
| 紧急接管 | 遥控器切出 `OFFBOARD` 后立即生效 |
| 降落上锁 | 实际触地后能完成触地确认并上锁，不因相对高度偏置持续转桨 |

### 不通过排查

| 现象 | 排查 |
|------|------|
| 切不过 Offboard | EKF2 融合状态？setpoint < 2 Hz？MAVROS local position 是否正常？ |
| 起飞前高度不是 0 | 正常；程序使用本次地面基准，不直接相信 QGC 的相对高度绝对值 |
| 电机转但不离地 | 电池电压、载重、桨叶方向、动力裕度；确认日志中是否已持续给 0.70m 台阶目标 |
| 40cm 附近停顿 | 检查是否有阶段脚本覆盖起飞参数；正常统一方案不会把 setpoint 回缩到当前高度 |
| 自动退出 Offboard | setpoint 间隔 > 0.5 秒，确保脚本未阻塞且 MAVROS 正常 |
| 落地后不停车 | 检查 `TOUCHDOWN_STALL_ALT_M` 和高度停滞日志；确认 `disarm` 服务调用成功 |
