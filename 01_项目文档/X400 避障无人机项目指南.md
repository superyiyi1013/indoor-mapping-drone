# Pixhawk 6C + X400 室内避障无人机项目指南

> 文档定位：本文件是项目总入口文档，用于说明系统目标、总体架构、硬件组成、软件结构、数据流、运行入口和团队协作方式。
>
> 维护原则：本文件只记录长期稳定的项目框架。阶段进度、测试结果、验收状态和问题记录放入 `03_SourceCode/test`，避免主指南频繁变成流水账。

---

## 1. 项目概览

### 1.1 项目目标

本项目以 **Pixhawk 6C 飞控 + X400 四旋翼机架** 为飞行平台，构建一套面向室内环境的低空定位、机载感知、前向避障和自主飞行验证系统。

系统设计目标如下：

| 目标 | 说明 |
|---|---|
| 室内无 GPS 飞行 | 依靠 Pixhawk 6C、MTF-02 光流测距和 PX4 EKF2 完成低空悬停与低速位移 |
| 机载计算接入 | 使用 Allspark2/Jetson 运行 ROS、MAVROS、D435i 数据处理和上层任务逻辑 |
| 前向深度避障 | 使用 Intel RealSense D435i 获取前方深度信息，输出近距障碍距离 |
| 安全可接管 | 保留遥控器、QGC、数传链路和 PX4 failsafe，自动能力不得绕过人工接管 |
| 可扩展自主飞行 | 在稳定基线上逐步扩展 Offboard 控制、视觉定位和更复杂任务逻辑 |

### 1.2 项目定位

本项目不是直接修改 PX4 底层固件的飞控研发项目，而是一个以 **PX4 稳定飞控能力 + 机载计算机上层感知决策** 为核心的工程集成项目。

核心分工：

```text
Pixhawk 6C / PX4
  负责姿态控制、位置控制、电机输出、模式管理和安全保护

Allspark2 / Jetson
  负责 ROS 节点、D435i 感知、MAVROS 通信、任务逻辑和后续视觉算法

地面端 / QGC / 遥控器
  负责参数配置、状态监控、日志查看和紧急人工接管
```

### 1.3 核心能力边界

本项目优先实现稳定、可验证、可接管的室内低速避障能力。

| 能力 | 项目内含义 |
|---|---|
| 定位 | 初期以 MTF-02 光流测距 + PX4 EKF2 为主 |
| 避障 | 初期以前向 D435i 深度距离检测、限速、悬停或中止任务为主 |
| 自主 | 初期以短距离 Offboard setpoint 控制为主 |
| 地面站 | QGC 作为调参、监控和日志工具，不作为唯一飞行依赖 |
| 视觉定位 | 作为后续扩展能力，需完成独立验证后再进入飞控闭环 |

### 1.4 系统设计原则

1. **飞控闭环优先**：Pixhawk 负责底层飞行稳定，机载电脑不直接驱动电机。
2. **低风险逐步闭环**：先旁路观测，再拆桨验证，最后低速上桨验证。
3. **保留可飞基线**：MTF-02 低空定位链路保留，新增模块不得破坏现有悬停能力。
4. **人工接管优先**：遥控器、QGC、failsafe 的优先级高于自动任务。
5. **模块化开发**：感知、通信、控制、启动、测试分层组织，便于团队成员并行开发。
6. **测试结果独立管理**：主指南不记录动态进度，阶段结果统一进入阶段测试管理文档。

### 1.5 双环境开发与运行边界

本项目采用 **Windows 主开发 + Linux 机载验证** 的双环境流程。两类自动飞行代码必须明确区分，避免路径、依赖和运行方式混用。

| 代码类别 | 路径 | 运行环境 | 通信方式 | 主要用途 |
|---|---|---|---|---|
| Windows MAVLink 远程验证 | `03_SourceCode/mavlink_auto_flight` | Windows 地面电脑 | 数传/UDP/串口 MAVLink | 起飞、悬停、降落、简单 Offboard 和飞行链路验证 |
| Linux MAVROS 飞行任务 | `03_SourceCode/mavros_auto_flight` | Linux 机载电脑 | MAVROS + Pixhawk T3 | 阶段06实飞任务（调用 flight_core） |
| Linux ROS 机载感知 | `03_SourceCode/ros_catkin_ws_lite/src` | Linux 机载电脑 | MAVROS + Pixhawk + D435i | 深度相机避障、MAVROS 配置、感知节点 |
| 共享飞行核心 | `03_SourceCode/flight_core` | 跨平台 Python | Transport 可插拔 | Fly 飞行原语，不依赖具体通信方式 |

开发原则：

1. `mavlink_auto_flight` 下的脚本默认在 Windows 地面电脑运行，不依赖 ROS。
2. `mavros_auto_flight` 下的任务脚本默认在 Linux 机载电脑运行，通过 MAVROS 连接 Pixhawk，调用 `flight_core` 的 Fly 原语。
3. ROS、MAVROS、D435i、避障和机载感知相关代码统一放入 `ros_catkin_ws_lite/src`，并按 catkin package 结构组织。
4. `flight_core` 不引入 ROS 或 pymavlink（仅在 `transport/` 实现中引入），Windows 和 Linux 可共用。
5. 飞行安全常量统一在 `flight_core/safety_config.py`，不在各 task 中分散定义。

### 1.6 不做什么

本项目当前不把以下内容作为第一版目标：

| 不做事项 | 原因 |
|---|---|
| 直接修改 PX4 控制器底层代码 | 调试风险高，不利于快速形成可飞系统 |
| 一开始实现完整三维自主绕障 | 需要稳定定位、地图、规划和大量安全验证 |
| 依赖 GPS 或室外导航能力 | 项目定位为室内低空无 GPS 场景 |
| 让机载电脑绕过 Pixhawk 控制电机 | 安全风险不可接受 |
| 把所有算法栈一次性并入工作区 | 编译、调试和责任边界会迅速失控 |

## 2. 系统总体架构

### 2.1 分层架构

```text
┌──────────────────────────────────────────────┐
│ 地面监控层                                    │
│ QGC / 地面电脑 / 遥控器 / 数传                 │
│ 负责：调参、监控、日志、人工接管                │
└───────────────────────┬──────────────────────┘
                        │ MAVLink / RC
┌───────────────────────▼──────────────────────┐
│ 机载计算层                                    │
│ Allspark2 / Jetson + ROS + MAVROS             │
│ 负责：D435i 数据处理、避障距离、任务逻辑         │
└───────────────────────┬──────────────────────┘
                        │ MAVLink UART
┌───────────────────────▼──────────────────────┐
│ 飞控执行层                                    │
│ Pixhawk 6C + PX4                              │
│ 负责：姿态/位置闭环、Offboard 执行、failsafe    │
└───────────────────────┬──────────────────────┘
                        │ PWM
┌───────────────────────▼──────────────────────┐
│ 动力执行层                                    │
│ PM06 / 电调 / 电机 / 桨叶 / X400 机架           │
│ 负责：供电、动力输出和机体承载                  │
└──────────────────────────────────────────────┘
```

### 2.2 总体拓扑

```text
                      ┌────────────────────────┐
                      │ 地面电脑 / QGC          │
                      │ 参数 / 状态 / 日志 / 监控 │
                      └───────────┬────────────┘
                                  │ LQ 2.4G 数传 / MAVLink
                                  ▼
┌──────────────┐       USB3       ┌────────────────────┐      UART MAVLink      ┌──────────────┐
│ Intel D435i  │ ───────────────→ │ Allspark2 / Jetson │ ─────T3/TELEM3──────→ │ Pixhawk 6C   │
│ 深度/RGB/IMU │                  │ ROS / MAVROS / 感知 │                       │ PX4 飞控闭环 │
└──────────────┘                  └────────────────────┘                       └──────┬───────┘
                                                                                       │
                           ┌───────────────────────────────────────────────────────────┤
                           ▼                                                           ▼
                    MTF-02 光流测距                                             电调 / 电机 / 桨叶
                    TELEM2 → PX4 EKF2                                           X400 四旋翼平台
```

### 2.3 关键链路

| 链路 | 用途 | 设计要求 |
|---|---|---|
| TELEM1 ↔ LQ 数传 | QGC 调参、监控、日志和备份链路 | 保留，不被机载电脑占用 |
| TELEM2 ← MTF-02 | 光流与测距输入 | 保留现有室内悬停基线 |
| T3/TELEM3 ↔ Allspark2/Jetson | MAVROS / Offboard / 避障数据 | TX/RX 交叉、GND 共地、波特率一致 |
| USB3 ↔ D435i | 深度图、RGB、IMU 数据 | 使用稳定 USB3 线，避免掉帧 |
| RC IN ← 接收机 | 人工接管 | 所有自动测试前必须确认有效 |

## 3. 硬件架构

### 3.1 核心硬件清单

| 模块 | 设备 | 职责 |
|---|---|---|
| 飞控 | Holybro Pixhawk 6C | PX4 飞行控制核心 |
| 机架 | X400 四旋翼机架 | 飞行平台和硬件承载 |
| 定位传感器 | MTF-02 光流测距一体传感器 | 室内低空光流与测距 |
| 机载计算机 | Allspark2 / Jetson NX | ROS、MAVROS、D435i、任务逻辑 |
| 深度相机 | Intel RealSense D435i | 前向深度感知，后续可用于视觉定位 |
| 通信 | LQ 2.4G 数传 | QGC 与 Pixhawk MAVLink 链路 |
| 动力 | X2212 KV980 电机 + XRotor 40A 电调 + 8038 桨 | 动力输出 |
| 电源 | 4S LiPo + PM06 电源模块 | 飞机供电、电压/电流采样 |

### 3.2 飞控端口分配

| Pixhawk 端口 | 连接设备 | 用途 |
|---|---|---|
| POWER1 | PM06 电源模块 | 飞控供电、电压/电流采样 |
| MAIN OUT 1-4 | 四个电调 | 电机 PWM 输出 |
| TELEM1 | LQ 2.4G 数传 | 地面 QGC 链路 |
| TELEM2 | MTF-02 | 光流与测距 |
| T3/TELEM3 | Allspark2/Jetson 串口1 | MAVROS / MAVLink / Offboard |
| RC IN | 接收机 | 遥控器输入 |
| USB | 调试电脑 | 固件、参数、日志、桌面调试 |
| GPS1/GPS2 | 不接 | 室内无 GPS 场景 |

### 3.3 供电与安装原则

| 项目 | 原则 |
|---|---|
| Pixhawk 供电 | 由 PM06 稳定供电 |
| Allspark2/Jetson 供电 | 独立隔离供电，不从 Pixhawk 取大电流 |
| D435i 供电 | 由机载电脑 USB3 提供 |
| 共地 | Pixhawk 与机载电脑串口通信必须共地 |
| 重心 | 新增机载电脑和 D435i 后必须重新检查重心 |
| 振动 | D435i、MTF-02、飞控固定需避免松动和强振动 |
| 散热 | 机载电脑上机后需确认温度和降频情况 |

### 3.4 D435i 安装方向

第一版安装方向采用 **前向避障优先**：

```text
D435i 朝机头正前方
  → 采集前方深度图
  → 检测 0.3-3 m 近距障碍
  → 输出距离给避障逻辑或 PX4 Collision Prevention
```

后续如果要做下向视觉定位，可再评估增加传感器或调整安装角度。主指南中的硬件架构只有在新增或调整硬件时再更新。

## 4. 软件架构

### 4.1 软件分层

| 层级 | 软件/模块 | 职责 |
|---|---|---|
| 飞控固件层 | PX4 | 飞行模式、EKF2、姿态/位置控制、failsafe |
| 通信桥接层 | MAVROS | ROS 与 Pixhawk MAVLink 之间的桥梁 |
| 传感器驱动层 | realsense-ros | D435i 深度图、RGB、IMU 数据发布 |
| 图像处理层 | NumPy | 深度图转换和 ROI 距离计算 |
| 避障感知层 | x400_perception | D435i 前向距离检测 |
| 启动编排层 | x400_bringup | 统一启动 MAVROS、D435i、避障节点 |
| 飞行核心层 | flight_core | Transport 通信抽象 + Fly 飞行原语（takeoff/hover/move/land），跨平台可复用 |
| 任务控制层 | mavros_auto_flight / mavlink_auto_flight | 阶段06实飞任务、起飞悬停降落脚本，调用 flight_core |

### 4.2 ROS 工作区

本项目 ROS 工作区为：

```text
03_SourceCode/ros_catkin_ws_lite
```

建议在机载电脑上的部署路径为：

```text
~/ros_catkin_ws_lite
```

目录职责：

| 路径 | 用途 |
|---|---|
| `src/x400_bringup` | 本项目启动包，负责组合 MAVROS、D435i、避障节点 |
| `src/x400_perception` | 本项目感知包，负责 D435i 前向障碍距离检测 |
| `src/realsense-ros` | RealSense D435i ROS 驱动 |

### 4.3 主要 launch 入口

| launch | 作用 |
|---|---|
| `x400_bringup/mavros_px4_t3.launch` | 只启动 MAVROS，验证机载电脑与 Pixhawk 通信 |
| `x400_bringup/d435i_front_distance.launch` | 启动 D435i 和前向距离检测 |
| `x400_bringup/onboard_sensing_stack.launch` | 自启动链路总入口：MAVROS + D435i + 前向距离 |
| `x400_perception/front_obstacle_distance.launch` | 只启动深度图转前向距离节点 |

### 4.4 编译与环境加载

在机载电脑上使用 ROS Noetic 时，标准流程为：

```bash
cd ~/ros_catkin_ws_lite
source /opt/ros/noetic/setup.bash
catkin_make
source devel/setup.bash
```

每次新开终端后，至少需要：

```bash
source /opt/ros/noetic/setup.bash
source ~/ros_catkin_ws_lite/devel/setup.bash
```

## 5. 数据流与控制流

### 5.1 MTF-02 定位数据流

```text
MTF-02
  ├─ OPTICAL_FLOW_RAD
  └─ DISTANCE_SENSOR
        ↓
Pixhawk TELEM2
        ↓
PX4 EKF2
        ↓
local_position / local_velocity
        ↓
位置控制 / 高度控制 / 姿态控制
```

MTF-02 是当前室内低空飞行的保底定位来源，新增 D435i 后仍然保留。

### 5.2 D435i 避障数据流

```text
D435i 深度图
        ↓
realsense2_camera
        ↓
/camera/depth/image_rect_raw
        ↓
x400_perception / front_obstacle_distance_node.py
        ↓
/x400/obstacle/front_distance
        ↓
/mavros/distance_sensor/rangefinder
        ↓
MAVROS distance_sensor
        ↓
MAVLink DISTANCE_SENSOR
        ↓
PX4 Collision Prevention / 上层任务限幅
```

第一版目标是让系统知道“前方最近障碍距离”，用于低速限幅、悬停或任务中止。

### 5.3 MAVROS 通信流

```text
Allspark2/Jetson ROS 节点
        ↓
MAVROS topic/service
        ↓
MAVLink over UART
        ↓
Pixhawk T3/TELEM3
        ↓
PX4 模式 / setpoint / telemetry
```

MAVROS 是机载电脑与 Pixhawk 之间的核心桥梁。所有机载控制指令都应通过 MAVROS/MAVLink 进入 Pixhawk，不绕过飞控。

### 5.4 地面监控与备份流

```text
QGC / 地面电脑
        ↓
LQ 2.4G 数传
        ↓
Pixhawk TELEM1
        ↓
参数 / 遥测 / 日志 / 模式监控
```

该链路保留为调试、监控和备份接管链路。机载电脑测试时，QGC 仍应能够查看飞机状态。

## 6. 启动与运行流程

### 6.1 只启动 MAVROS

用途：验证机载电脑能否连接 Pixhawk。

```bash
cd ~/ros_catkin_ws_lite
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch x400_bringup mavros_px4_t3.launch fcu_url:=/dev/ttyTHS0:921600 gcs_url:=udp-b://@14550
```

验证：

```bash
rostopic echo /mavros/state
```

通过标准：

```text
connected: True
```

### 6.2 只启动 D435i 避障感知

用途：验证 D435i 是否有深度图，避障节点是否能输出距离。

```bash
cd ~/ros_catkin_ws_lite
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch x400_bringup d435i_front_distance.launch
```

验证：

```bash
rostopic hz /camera/depth/image_rect_raw
rostopic echo /x400/obstacle/front_distance
rostopic echo /mavros/distance_sensor/rangefinder
```

### 6.3 开机自启动完整机载避障链路

用途：机载电脑上电后由 systemd 自动启动 MAVROS、D435i 和前向距离检测，阶段06前只做健康检查。

```bash
cd ~/ros_catkin_ws_lite
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch x400_bringup onboard_sensing_stack.launch fcu_url:=/dev/ttyTHS0:921600
```

验证关键项：

| 检查项 | 命令/方法 | 通过标准 |
|---|---|---|
| MAVROS | `rostopic echo /mavros/state` | `connected: True` |
| 深度图 | `rostopic hz /camera/depth/image_rect_raw` | 连续输出 |
| 避障距离 | `rostopic echo /mavros/distance_sensor/d435i_front_sub` | 距离随障碍物变化 |
| QGC 检查 | MAVLink Inspector | 可见对应 `DISTANCE_SENSOR` |

## 7. 安全策略

### 7.1 控制权优先级

```text
人工遥控器 / 安全员
        高于
QGC 模式切换 / 降落命令
        高于
PX4 failsafe / Offboard 超时保护
        高于
机载电脑自动任务
```

自动任务必须服从人工接管，不允许让机载电脑成为唯一控制源。

### 7.2 起飞前安全约束

任何上桨飞行前，必须确认：

| 检查项 | 要求 |
|---|---|
| 遥控器 | 通道正常，模式切换正常 |
| QGC | 可看到姿态、电池、模式、消息 |
| MTF-02 | `DISTANCE_SENSOR` 与 `OPTICAL_FLOW_RAD` 正常 |
| MAVROS | `/mavros/state connected: True` |
| D435i | 深度图稳定，距离值随障碍物变化 |
| 接管 | 自动任务中能退出或切回人工 |
| 桨叶 | 仅在拆桨验证通过后安装 |

### 7.3 故障降级

| 故障 | 处理原则 |
|---|---|
| MAVROS 断开 | 停止 Offboard 任务，进入人工或 PX4 安全模式 |
| D435i 掉线 | 禁止继续主动前进，任务进入 HOLD/LAND/等待接管 |
| 视觉数据跳变 | 不直接进入 EKF 闭环，先旁路记录和对比 |
| Allspark2 掉电 | Pixhawk 与 MTF-02、数传和遥控器仍应保留基本控制能力 |
| QGC 失联 | 遥控器仍可接管 |
| 电源异常 | 终止测试，优先保护人员和设备 |

### 7.4 禁止事项

1. 禁止在未拆桨验证前直接运行新 Offboard 控制脚本。
2. 禁止用机载电脑直接控制电机或绕过 Pixhawk。
3. 禁止在遥控接管未验证时进行自动飞行。
4. 禁止在 QGC 看不到关键传感器数据时测试避障飞行。
5. 禁止把未验证的视觉定位直接写入 PX4 EKF2 闭环。

## 8. 团队开发规范

### 8.1 角色分工

| 方向 | 主要职责 |

### 8.2 文档分工

| 文档区域 | 作用 |
|---|---|
| `01_项目文档` | 稳定架构、项目说明、硬件框架、团队入口 |
| `02_固件与配置` | PX4 固件、参数文件、参数变更记录 |

### 8.3 变更原则

1. 主指南只在架构、硬件、软件栈或安全策略变化时更新。
2. 阶段进展和测试结论写入阶段测试管理，不写入主指南。
3. 参数变更必须保存参数文件和变更说明。
4. 飞行脚本变更后必须先拆桨验证。
5. 新成员先读主指南，再按阶段测试文档执行具体测试。

## 9. 常见问题排查入口

### 9.1 MAVROS 连不上

优先检查：

1. Pixhawk 是否上电。
2. T3/TELEM3 与机载电脑串口1是否接对。
3. TX/RX 是否交叉，GND 是否共地。
4. Linux 串口名是否正确。
5. `fcu_url` 与 PX4 串口波特率是否一致。
6. PX4 对应 MAVLink 实例是否启用。

### 9.2 D435i 没有深度图

优先检查：

1. 是否使用 USB3。
2. `rs-enumerate-devices` 是否能看到设备。
3. 是否有其他程序占用 D435i。
4. 分辨率和帧率是否过高。
5. 机载电脑供电是否稳定。

### 9.3 QGC 看不到 `DISTANCE_SENSOR`

优先检查：

1. `/mavros/distance_sensor/rangefinder` 是否有数据。
2. MAVROS 是否 connected。
3. MAVROS distance_sensor 插件是否启用。
4. QGC MAVLink Inspector 是否选中正确车辆。
5. PX4 Collision Prevention 参数是否保存并重启生效。

### 9.4 Offboard 不能进入

优先检查：

1. MAVROS 是否连接。
2. setpoint 是否提前连续发送。
3. PX4 当前模式和解锁状态是否满足要求。
4. RC / failsafe / EKF 状态是否阻止进入 Offboard。
5. 本地位置估计是否有效。

## 10. 后续扩展路线

### 10.1 第一类扩展：前向避障能力增强

| 方向 | 说明 |
|---|---|
| 多 ROI 检测 | 将画面分成左/中/右区域，判断障碍方向 |
| 距离滤波 | 对深度距离做滑动平均、中值滤波和异常值剔除 |
| 任务限幅 | 前方过近时限制前进速度或中止前进 setpoint |
| CP 参数优化 | 根据实飞速度、刹停距离和场地调整 PX4 CP 参数 |

### 10.2 第二类扩展：Offboard 任务控制

| 方向 | 说明 |
|---|---|
| 起飞悬停 | 稳定 0.5-1.0 m 低空悬停 |
| 短距离位移 | 0.3-0.5 m 小范围前后左右移动 |
| 安全边界 | 以起飞点为中心限制最大水平距离 |
| 任务中止 | 障碍、失联、越界时自动 HOLD/LAND/等待接管 |

### 10.3 第三类扩展：视觉定位

视觉定位作为后续能力，不应在前向避障未验证前直接进入飞控闭环。

推荐路线：

```text
D435i 图像/IMU 旁路记录
        ↓
桌面和手持验证 VIO/SLAM
        ↓
与 PX4 local_position 对比
        ↓
校准坐标系、延迟和外参
        ↓
再评估是否进入 EKF2 External Vision
```

### 10.4 第四类扩展：任务级自主

在定位、避障和安全接管都稳定后，再考虑：

- 简单航点任务。
- 室内固定路线巡航。
- 目标识别与任务触发。
- 轻量路径规划。
- 更复杂的自主绕障。
