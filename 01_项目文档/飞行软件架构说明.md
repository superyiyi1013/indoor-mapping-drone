# 飞行软件架构说明

> 本文档描述 X400 项目的飞行软件架构。硬件接线、端口分配见 `项目硬件框架与端口分配.md`。

---

## 1. 架构总览：Transport → Fly → Task

飞行代码采用三层分离架构，核心在 `03_SourceCode/flight_core/`。

```
┌─────────────────────────────────────────────────────────┐
│                  Task 层（任务编排）                        │
│  mavros_auto_flight/tasks/*.py                           │
│  mavlink_auto_flight/takeoff_hover_flight_core.py        │
│                                                         │
│  hover_takeover.py     "起飞→悬停→等待接管"                │
│  low_alt_hover.py      "起飞→悬停→降落"                   │
│  short_forward.py      "起飞→悬停→前进→悬停→降落"          │
│  obstacle_stop.py      "起飞→悬停→前进(遇障停止)→降落"     │
│                                                         │
│  每个 task 只描述"做什么"，调用 Fly 层原语                   │
└───────────────────────┬─────────────────────────────────┘
                        │ 调用
┌───────────────────────▼─────────────────────────────────┐
│                 Fly 层（飞行原语）                          │
│  flight_core/fly.py                                      │
│                                                         │
│  takeoff(alt_m)      起飞：起跳检测→爬升速率控制→高度上限    │
│  hover(duration_s)   定点悬停（以起飞基准 XY 为准）          │
│  move_forward(d,s)   沿机头方向前进                         │
│  move_forward_until  前进直到满足停止条件                   │
│  land()              下降→高度交接→NAV_LAND                │
│                                                         │
│  所有安全边界来自 safety_config.py，不依赖具体通信方式        │
└───────────────────────┬─────────────────────────────────┘
                        │ 依赖 Transport 接口
┌───────────────────────▼─────────────────────────────────┐
│              Transport 层（通信适配）                       │
│  flight_core/transport/                                  │
│                                                         │
│  ┌─────────────────────┐  ┌──────────────────────────┐  │
│  │ MavlinkTransport    │  │ MavrosTransport           │  │
│  │ pymavlink 直连       │  │ ROS topic + service       │  │
│  │ Windows 地面电脑      │  │ Linux 机载电脑             │  │
│  └─────────────────────┘  └──────────────────────────┘  │
│                                                         │
│  统一接口（Transport ABC）：                               │
│    get_state()  send_setpoint_local()  set_mode()        │
│    arm()  disarm()  send_land()                          │
└─────────────────────────────────────────────────────────┘
```

**设计要点**：

- Fly 层不 `import rospy`，也不 `import pymavlink`——它只跟 `Transport` 接口对话。
- Transport 实现各自处理自己的通信细节（ROSTopic vs MAVLink 消息）。
- Task 层不直接调 Transport 的方法，只调 Fly 的原语。
- 安全常量集中管理在 `safety_config.py`，task 层不写死高度/速度/超时值。

## 2. 三个包/文件夹的分工

### 2.1 `flight_core/` — 共享飞行核心

| 文件 | 职责 |
|:---|:---|
| `transport/__init__.py` | Transport 抽象接口定义（`Transport` ABC + `VehicleState` 数据类） |
| `transport/mavros_transport.py` | MAVROS 通信实现，运行于 Linux 机载电脑 |
| `transport/mavlink_transport.py` | pymavlink 直连实现，运行于 Windows 地面电脑 |
| `fly.py` | Fly 层，所有飞行原语的实现 |
| `safety_config.py` | 全局安全常量：高度上限、速度上限、超时阈值 |
| `task_runner.py` | Task 层统一入口：参数解析 → 安全确认 → Fly 连接 → 异常兜底 |
| `README.md` | flight_core 使用文档 |

**依赖关系**：
- `fly.py` 依赖 `transport/__init__.py`（只依赖 ABC 接口，不依赖具体实现）
- `task_runner.py` 依赖 `fly.py` + `transport/__init__.py`
- `safety_config.py` 纯常量，无任何依赖
- `mavros_transport.py` 依赖 `rospy` + `mavros_msgs` + `sensor_msgs`（只在 Linux ROS 环境可用）
- `mavlink_transport.py` 依赖 `pymavlink`（Windows和Linux都能装）

### 2.3 `mavlink_auto_flight/` — Windows 地面 MAVLink 验证

> 运行环境：Windows 地面电脑 + pymavlink。通过数传电台 / UDP / 串口连接 Pixhawk TELEM1。


**两条线的关系**：

| | 原版 | flight_core 版 |
|:---|:---|:---|
| 文件 | `takeoff_hover_test.py` | `takeoff_hover_flight_core.py` |
| 底层 | pymavlink 直调 | MavlinkTransport → Fly |
| 独立运行 | ✅ 无需 flight_core | 需要 PYTHONPATH 指向 flight_core |

> 建议：日常快速验证用原版，最终飞行前用 flight_core 版确认两端的飞行行为一致。

## 3. 飞行原语详解

所有原语均在 `fly.py` 的 `Fly` 类中实现，同步阻塞。安全参数默认值来自 `safety_config.py`。

### takeoff(target_alt_m)

```
流程：
  1. get_state() → 缓存 home_x / home_y / home_z
  2. 预发 setpoint (2s) → 切 OFFBOARD → 再发 1s → 解锁
  3. 起跳段：给 0.40m 目标 → 检测相对高度 ≥ 0.15m → 确认离地（6s 超时）
  4. 爬升段：以 0.30 m/s 爬升 → 到达 target_alt_m
      途中检测高度 > 2.0m 则抛异常
      爬升超过 20s 未到达则超时
  5. 打印 "到达目标高度"，返回
```

### hover(duration_s, alt_m=None)

```
  - 以 home_x / home_y 为固定 XY（不随漂移移动）
  - alt_m 指定则保持该绝对高度，否则保持当前高度
  - 每秒打印一次高度和剩余时间
```

### move_forward(distance_m, speed_mps, alt_m=None)

```
  - 从 get_state().yaw 获取当前机头方向
  - 线性插值：从 home 点出发，终点 = home + (cos(yaw)*d, sin(yaw)*d)
  - distance_m 正=前，负=后
  - speed_mps 默认 0.15，上限 0.30
  - distance 上限 1.0m
```

### move_forward_until(max_dist_m, stop_condition, ...)

```
  - 与 move_forward 类似，但每步调用 stop_condition(state)
  - stop_condition 返回 True 时立即停止
  - 典型用法：stop_condition=lambda s: s.front_distance_m <= 1.0
  - 返回实际移动距离
```

### land()

```
  - 以 0.20 m/s 下降到 LAND_HANDOFF_ALT_M(0.45m)
  - 发送 NAV_LAND 交给 PX4 自动降落
  - 降落超时(25s)也会强制发 NAV_LAND
```

## 4. 安全常量清单

全部定义在 `flight_core/safety_config.py`，现场可通过环境变量或代码覆盖。

| 常量 | 默认值 | 说明 |
|:---|:---:|:---|
| `MAX_SAFE_ALT_M` | 2.0 | 绝对安全高度上限（超过则中止任务） |
| `MAX_TASK_ALT_M` | 1.0 | 任务默认允许最高高度 |
| `LIFTOFF_TARGET_ALT_M` | 0.40 | 起跳指令目标高度 |
| `LIFTOFF_DETECTED_ALT_M` | 0.15 | 确认为"已离地"的相对高度 |
| `CLIMB_RATE_MPS` | 0.30 | 爬升速率 |
| `DESCEND_RATE_MPS` | 0.20 | 下降速率 |
| `LAND_HANDOFF_ALT_M` | 0.45 | 交给 PX4 NAV_LAND 的高度 |
| `MAX_FORWARD_DISTANCE_M` | 1.0 | 单次前进最大距离 |
| `MAX_FORWARD_SPEED_MPS` | 0.3 | 前进最大速率 |
| `SETPOINT_HZ` | 10.0 | setpoint 发布频率 |

## 5. 编写新 Task 的标准模板

```python
#!/usr/bin/env python3
import os, sys
sys.path.insert(0, os.path.abspath(os.path.join(
    os.path.dirname(__file__), "..", "..")))

from flight_core.task_runner import run_task
from flight_core.transport.mavros_transport import MavrosTransport


def add_args(parser):
    """注册任务专属命令行参数"""
    parser.add_argument("--my-param", type=float, default=0.5)


def run(fly, args):
    """任务主逻辑：只调 Fly 原语，不调 transport"""
    fly.takeoff(args.alt)
    fly.hover(args.hover_time)
    fly.move_forward(args.my_param, alt_m=args.alt)
    fly.hover(args.hover_time)
    fly.land()


if __name__ == "__main__":
    sys.exit(run_task("my_task", add_args, run, MavrosTransport()))
```

配套 Shell 入口（放在 `stage06_xx_xxx.sh`）：

```bash
#!/usr/bin/env bash
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
MY_PARAM="${MY_PARAM:-0.5}"
ALT="${ALT:-0.8}"
HOVER_TIME="${HOVER_TIME:-6}"

source "$SCRIPT_DIR/common/env_setup.sh"
run_flight_task "XX_任务名" "tasks/my_task.py" \
  --alt "$ALT" --hover-time "$HOVER_TIME" --my-param "$MY_PARAM"
```

## 6. 与硬件架构的对应关系

| 硬件链路 | 软件层 | 说明 |
|:---|:---|:---|
| Pixhawk TELEM3 → Allspark/Orin | MavrosTransport | 机载 MAVROS 通信 |
| LQ 2.4G 数传 → TELEM1 | MavlinkTransport | 地面站 pymavlink 直连 |
| D435i USB3 → Allspark/Orin | x400_perception | 前向障碍距离节点 |
| MTF-02 → TELEM2 | PX4 EKF2（不经过本项目代码） | 光流+测距定位 |
| 遥控器 → RC IN | PX4 直接处理 | 人工接管最高优先级 |
