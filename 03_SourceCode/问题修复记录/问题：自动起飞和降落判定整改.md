# 问题：自动起飞和降落判定整改

## 问题现象

1. 起飞阶段不够一致：部分测试中电机已响应，但飞机离地存在延迟；进入爬升阶段时曾出现 setpoint 回缩，导致飞机在约 0.4m 附近停顿或短暂下降。
2. 降落阶段不能可靠停桨：飞机已物理触地后，相对高度读数仍稳定在约 0.15m，旧逻辑等待 `rel_alt < 0.05m`，导致触地判定不触发、螺旋桨持续转动。
3. QGC/MAVROS 相对高度零点不稳定：飞机在地面时高度可能显示 0.5m、1.1m 等，不能直接把显示高度作为真实离地高度。

## 原因判断

1. 起飞前未对当前地面高度进行采样，直接使用飞行器上电初期的 local_position 值作为基准，该值可能因光流/EKF 初始化而不稳定。
2. 原 `_climb_to_altitude()` 中，爬升起始高度 `climb_start_alt` 仅被钳位到 `LIFTOFF_DETECTED_ALT_M`（旧值 0.25/0.40），未钳位到台阶目标高度（0.60m）。离地保持结束时 setpoint 从 0.60m 回缩到检测高度（约 0.41m），导致短暂下降。
3. 各 task 脚本曾独立覆盖 `LIFTOFF_ALT`、`CLIMB_RATE` 等参数，同一套 `fly.py` 在不同任务下起飞行为不一致。
4. 降落触地判定仅依赖单层固定阈值 `rel_alt < 0.05m`，无法处理 EKF 高度漂移导致落地后读数停在 0.15m 的情况。

## 本次修改

### `flight_core/safety_config.py`

| 参数 | 旧值 | 新值 | 说明 |
|---|---|---|---|
| `GROUND_BASELINE_DURATION_S` | — | **2.5** | 新增。起飞前采样地面静止位置时长，取均值作为本次高度基准 |
| `LIFTOFF_DETECTED_ALT_M` | 0.40 | **0.20** | 离地检测阈值降低。配合地面基准采样后，0.20m 代表"明确离地" |
| `LIFTOFF_SETTLE_ALT_M` | — | **0.0** | 新增但值为 0，取消额外的起跳稳定高度门槛 |
| `CLIMB_RATE_MPS` | 0.30 | **0.20** | 降低爬升速率，使爬升段 setpoint 更贴近飞机实际爬升能力 |
| `TOUCHDOWN_ALT_THRESHOLD_M` | 0.05 | **0.15** | 硬触地阈值。实测 EKF 偏移下地面高度稳定在 0.15m |
| `TOUCHDOWN_STALL_ALT_M` | — | **0.30** | 新增。低空停滞触地判定的高度上限 |
| `TOUCHDOWN_STALL_COMMAND_ALT_M` | — | **0.25** | 新增。下降目标进入该高度后启动低空停滞观察 |
| `TOUCHDOWN_STALL_DELTA_M` | — | **0.05** | 新增。确认时间内高度变化小于该值视为触地停滞 |
| `TOUCHDOWN_BOTTOM_HOLD_S` | — | **3.0** | 新增。下降目标压到 0 后延时上锁 |
| `TOUCHDOWN_BOTTOM_ALT_M` | — | **0.35** | 新增。到位兜底允许的最大相对高度 |

### `flight_core/fly.py`

**新增 `_record_ground_baseline()`**
- 起飞前 2.5s 以 10Hz 采样 local_position（x, y, z），取均值作为本次飞行的 home 基准
- 打印采样结果，直观显示本次基准值

**重写 `_liftoff_from_ground()`**
- 不再将"离地检测"作为阶段切换点。检测到 `rel_alt >= 0.20m` 仅记录日志和保持计时
- 保持 0.8s 后直接返回，不改变 setpoint
- 全程发送 `liftoff_z`（home_z - 0.60m）

**修改 `_climb_to_altitude()` 调用方式**
- 调用时传入 `liftoff_alt_m`（0.60m）作为 `climb_start_alt`
- `climb_start_alt = min(max(0.60, LIFTOFF_DETECTED_ALT_M=0.20), target=1.0) = 0.60`
- 爬升段第一帧 setpoint = 0.60m，与离地保持段最后一帧一致，消除回缩

**重写 `land()` 触地判定为三层逻辑**
- 第一层 硬触地：`rel_alt < 0.15m` 持续 2.0s → disarm
- 第二层 低空停滞：下降目标 ≤ 0.25m 且高度 ≤ 0.30m，确认 2.0s 内高度变化 ≤ 0.05m → disarm
- 第三层 到位兜底：下降目标压到 0 且高度 ≤ 0.35m，等待 3.0s → disarm
- 任一层满足即触发，避免单层失效导致不停桨

**抽取 `_disarm_after_touchdown(reason)`**
- 统一上锁逻辑，输出触发层信息

### Task 层（`mavros_auto_flight/tasks/` 和 `mavros_auto_flight/*.sh`）

- 去掉所有 bash 脚本对 `LIFTOFF_ALT` 的环境变量覆盖
- 去掉所有 Python task 中的 `--liftoff-alt`、`--climb-speed`、`--climb-timeout` 参数定义
- 去掉 task 中 `sc.LIFTOFF_TARGET_ALT_M`、`sc.CLIMB_RATE_MPS` 的运行时覆盖
- 所有 task 统一调用 `fly.takeoff(target_alt_m)`，由 `flight_core` 内部统一控制起飞流程

## 后续验证要点

1. 运行阶段06/07任意脚本时，日志应出现统一起飞流程（地面基准采样 → 台阶起跳 → 单调爬升），不应再出现单独覆盖起飞参数的输出。
2. 起飞应先明确离地，再柔和爬升到目标高度，不能出现 setpoint 回缩。
3. 降落到地面后，即使相对高度停在约 0.15m，也应触发触地确认并上锁。
4. Jetson 端必须同步最新 `03_SourceCode/flight_core`，且 `FLIGHT_CORE_DIR` 不应指向旧目录。
