# 问题：起跳段超时判定过于刚性，低电量时爬升略慢即失败

## 背景

阶段07_00 测试中，电池电量约 60% 时起飞失败。日志显示高度已经攀升到 0.37m（仅差 3cm 达到检测阈值 0.40m），但因为 6 秒超时到期，被判定为"起跳超时"，抛异常进入兜底降落。

## 根因

起跳段 `_liftoff_from_ground()` 使用**固定 6 秒超时**，检测到 `rel_alt ≥ 0.40m` 才算成功。但：

- 电池电压越低 → 同油门转速越低 → 爬升越慢
- 60% 电量时，从电机启动到离地需要 4-5 秒，而满电时只需 2-3 秒
- 6s 一刀切超时在满电时合理，但在低电量时过于严格

**关键矛盾**：高度已经持续增长（0.24→0.28→0.37），飞机确实在离地，只是因为爬升速率略慢于满电状态就被判定为失败。

## 改动

`fly.py` — `_liftoff_from_ground()` 新增双重超时保护：

### 第一层保险：高度停滞检测

不是简单地等够某个时间，而是**跟踪高度是否在持续增加**：

```python
if rel_alt > last_rel_alt + 0.01:  # 有进步（>1cm）
    stagnant_start = None            # 重置停滞计时
else:
    if stagnant_start is None:
        stagnant_start = now
    elif now - stagnant_start > 3.0: # 连续 3s 高度不涨
        raise FlyError("起跳停滞超过 3s，请检查动力/载重/定高/电池")
```

只要高度在涨（哪怕很慢），就不会触发超时。只有连续 3 秒高度完全不涨，才判定为真失败。

### 第二层保险：总超时延长至 12 秒

作为硬性安全兜底，防止某些极端情况下无限等待。

### 效果对比

| 场景 | 旧逻辑 | 新逻辑 |
|---|---|---|
| 满电正常起飞 | ✅ 3s 完成，不受影响 | ✅ 同样正常 |
| 60% 电爬升慢（0.24→0.28→0.37...） | ❌ 6s 超时抛异常 | ✅ 高度仍在增长，继续等待 |
| 电机故障完全不转 | ❌ 6s 后才知道 | ✅ 3s 停滞即判定失败，反应更快 |
| 飞机被卡住高度不动 | ❌ 6s 超时 | ❌ 3s 停滞即判定 |

## 验证要点

1. 运行 `stage07/00_takeoff_hover_land.sh`，满电时应正常起飞
2. 如果有条件，在 60% 电量下再次验证，应能正常完成起跳
3. 若出现停滞故障，日志应输出 `"起跳停滞超过 3s"` 而非 `"起跳超时"`
4. 12s 硬上限作为兜底，正常情况下不应触发
